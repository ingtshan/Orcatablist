### R3 解析（`src/parse.ts`，纯函数，可单测）
`parseLine(line: string): ParsedEvent`：
1. JSON 解析失败 → `{kind:"skip"}`（不抛）。
2. `type === "ai-title"` → `{kind:"title", title: aiTitle.trim()}`（空串视为 skip）。
3. `type === "user"` 且 `isMeta !== true` 且（`message.content` 为非空字符串，或为数组且 `content[0].type === "text"` 且 text 非空）→ `{kind:"prompt", text, ts}`。纯 `tool_result` 的 user 行、`isMeta:true` 行 → skip。
4. `type === "assistant"` 且 `message.content` 为数组 → 把所有 `type==="text"` 块的 text 用 `\n` 拼接；非空则 `{kind:"assistant-text", text, ts}`，否则 skip（thinking / tool_use 不索引）。
5. 任何带 `cwd` 的行，额外可作 `{kind:"meta", cwd, branch: gitBranch, version}` 使用——实现上：`parseLine` 返回主事件时把 `cwd/branch/version` 一并挂在事件上（若该行有），indexer 只在会话尚无 cwd 时采用。
6. 其余类型（`attachment`、`file-history-snapshot`、`mode`、`permission-mode`、`atis-latch`、`last-prompt`、`system`、未知）→ skip。
7. `ts` = `Date.parse(timestamp)`，无效或缺失 → null。
8. 显示用清洗函数 `cleanPromptForDisplay(text)`：去掉所有 `<…>` 标签，折叠连续空白为单空格，trim，截到 `FIRST_PROMPT_MAX_CHARS`。

### R4 数据库（`src/db.ts`）
schema 逐字：
```sql
CREATE TABLE IF NOT EXISTS meta (key TEXT PRIMARY KEY, value TEXT);
CREATE TABLE IF NOT EXISTS sessions (
  sid TEXT PRIMARY KEY, project_key TEXT NOT NULL, cwd TEXT, git_branch TEXT,
  title TEXT, first_prompt TEXT, last_input_at INTEGER, prompt_count INTEGER NOT NULL DEFAULT 0,
  file_path TEXT NOT NULL, file_size INTEGER NOT NULL DEFAULT 0, file_mtime INTEGER NOT NULL DEFAULT 0,
  parsed_offset INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS sessions_last ON sessions(last_input_at DESC);
CREATE TABLE IF NOT EXISTS projects (key TEXT PRIMARY KEY, name TEXT NOT NULL, root TEXT NOT NULL, color TEXT);
CREATE TABLE IF NOT EXISTS cwd_cache (cwd TEXT PRIMARY KEY, project_key TEXT NOT NULL);
CREATE VIRTUAL TABLE IF NOT EXISTS msg_fts USING fts5(text, sid UNINDEXED, role UNINDEXED, ts UNINDEXED, tokenize='trigram');
```
- `meta.schema_version = "1"`；版本不匹配时删库重建（DB 只是缓存）。
- `PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL;`
- 导出的查询函数（签名可微调，语义冻结）：`upsertSession`、`replaceSessionFts(sid, rows)`、`deleteSessionFts(sid)`、`listProjects(): ProjectRow[]`、`listSessions({projectKey?, limit}): SessionRow[]`（不含 live，按 `last_input_at DESC NULLS LAST`）、`search(q, limit): {sid, role, ts, snippet, score}[]`、`getSession(sid)`。
- `search`：`q.trim().length >= SEARCH_MIN_FTS_CHARS` → `WHERE msg_fts MATCH ? ORDER BY rank`，MATCH 参数 = `'"' + q.replace(/"/g,'""') + '"'`，`snippet(msg_fts, 0, '‹', '›', '…', 20)`，`score = -rank`；否则 `WHERE text LIKE ? ESCAPE '\'`（`%`、`_`、`\` 转义），片段取首个命中前后各 40 字并用 ‹› 包裹，`score = 1`。每次最多取 `limit*3` 行，再按 sid 聚合（每会话 ≤ 3 条 hit，按 score 最高者排序），返回 ≤ `limit` 个会话。

### R5 项目归并（`src/projects.ts`）
`resolveProjectKey(cwd: string | null, deps): {key, name, root}`，规则按顺序：
1. `cwd` 为 null 或不是绝对路径 → `{key:"unknown", name:"未知", root:""}`。
2. `git -C <cwd> rev-parse --path-format=absolute --git-common-dir` 成功（exit 0）→ `root` = 结果去掉末尾 `/.git`（若不以 `/.git` 结尾则原样），`key = root`，`name = basename(root)`。本机事实：`/Users/bb00/workspace/y-feibo/lumina--wp/lumina-main`、`…/lumina-payment-hotfix`、`/Users/bb00/orca/workspaces/lumina/micro-classromm-study` 的 common-dir 都是 `/Users/bb00/workspace/y-feibo/lumina--wp/lumina/.git`，必须归入同一组。
3. git 失败（cwd 不存在 / 非仓库）且 cwd 匹配 `^(.*/orca/workspaces/([^/]+))/` → `key = "orca-workspaces:" + repoName`，`name = repoName`，`root = ""`。
4. 否则 `key = cwd`，`name = basename(cwd)`，`root = cwd`。
- 后处理合并：若某个 `orca-workspaces:<name>` 键与另一个项目的 `name` 相同，则归入那个项目（改写 sessions.project_key）。
- 显示名/颜色：启动时和之后每 10 分钟执行 `orca repo list --json`（失败静默，用默认名），取 `result.repos[]` 的 `{path, displayName, badgeColor}`；`path === root` 时用 `displayName` 作 name、`badgeColor` 作 color（样例值 `"#737373"`）。
- 结果写入 `cwd_cache`，同一 cwd 只解析一次；`git` 通过 `Bun.spawn` argv 调用，超时 3 s。

### R6 在线状态（`src/live.ts`）
- 读 `<ORCATAB_CLAUDE_DIR>/sessions/*.json`（目录缺失 → 空）；每个文件 → `{sessionId, pid, status, waitingFor ?? null, name ?? null}`。
- 存活判定 `process.kill(pid, 0)`：正常 → 存活；`ESRCH` → 死；`EPERM` → 存活。死的不返回。
- `status` 不在 `LiveStatus` 内时映射为 `"idle"`。
- 结果缓存 `LIVE_CACHE_MS`；导出 `getLiveMap(): Map<sid, LiveInfo>`、`findLive(sid)`。

### R7 索引器（`src/indexer.ts`）
- 发现：`<ORCATAB_CLAUDE_DIR>/projects/*/` 下直接子文件、文件名匹配 `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}\.jsonl$/`；忽略 `agent-*.jsonl`、`journal.jsonl`、所有子目录。
- 每文件比对 `(size, mtime)` 与库中记录：未变 → 跳过；size 变大 → 从 `parsed_offset` 用 `fs.openSync` + `readSync` 读到末尾；size 变小 → `deleteSessionFts(sid)`，全部字段重置后从 0 读。
- 只按 `\n` 切整行；最后一段若不以 `\n` 结尾则不消费，`parsed_offset` 停在最后一个完整行之后。按字节计算 offset（UTF-8），不要用字符数。
- 每行 `parseLine`：title → 覆盖 `title`；prompt → `prompt_count++`、`last_input_at = max(旧值, ts)`、首条时设 `first_prompt = cleanPromptForDisplay(text)`；prompt 与 assistant-text 都写 fts（text 截到 `FTS_TEXT_MAX_CHARS`）；meta 仅在会话尚无 cwd 时采用。
- 每个文件一个事务；先 `resolveProjectKey`，再 upsert。
- 导出 `indexAll(): {files, changed, ms}` 与 `startRescanTimer()`（`RESCAN_INTERVAL_MS`，用 `setInterval`，串行防重入）。
- 目标：本机 88 文件首次建库 < 2 s（含 fts 写入）。

### R8 定位（`src/focus.ts`）
`resolveFocus(sid, deps, {dryRun}): Promise<FocusResult>`，`deps` 注入以便测试：`{ findLive(sid), getSessionCwd(sid), psEnv(pid): Promise<string>, orcaJson(args: string[]): Promise<{ok:boolean, result?:any, error?:any}>, openOrca(): Promise<void> }`。
1. `sid` 不匹配 UUID 正则 → 抛 `ValidationError`（HTTP 400）。
2. `live = findLive(sid)`：
   - 有：`env = psEnv(pid)`（真实实现：`ps -Eww -o command= -p <pid>`，输出形如 `claude --effort max TERM_PROGRAM=Orca ORCA_WORKTREE_ID=… ORCA_TERMINAL_HANDLE=term_ea8b… ORCA_TAB_ID=…`，按空格切分取 `ORCA_TERMINAL_HANDLE=` 与 `ORCA_TAB_ID=` 之后的值）。
     - 有 handle：非 dryRun 时先 `openOrca()`（`open -a Orca`，失败忽略）再 `orcaJson(["terminal","switch","--terminal",handle,"--json"])`；`ok` → `{action:"switched", handle, tabId: result.focus?.tabId ?? ORCA_TAB_ID ?? null}`；`ok=false` → 抛 `OrcaError`（HTTP 500，带 error 文本）。dryRun → 直接返回 switched（不调用 openOrca/switch）。
     - 无 handle → `{action:"manual", reason:"running-outside-orca", command: null}`。
   - 无：`cwd = getSessionCwd(sid)`；找不到会话 → `{action:"manual", reason:"unknown-session", command:null}`。
     - `orcaJson(["worktree","show","--worktree","path:"+cwd,"--json"]).ok` → 非 dryRun 时 `orcaJson(["terminal","create","--worktree","path:"+cwd,"--title","claude --resume","--command","claude --resume "+sid,"--json"])`，handle 取 `result.terminal?.handle ?? result.handle ?? result.startupTerminal?.handle`（先运行 `orca terminal create --help` 与 `orca skills get orca-cli` 确认响应形状，把实际字段写进报告），随后 `terminal switch` → `{action:"resumed", handle}`；dryRun → 返回 `{action:"resumed", handle:"(dry-run)"}`。
     - 否则 → `{action:"manual", reason:"not-orca-worktree", command:"cd "+shellQuote(cwd)+" && claude --resume "+sid}`。
3. CLI 入口（同一文件，`import.meta.main`）：`bun src/focus.ts [--dry-run] <sid | orcatab://claude/<sid>>`，输出一行 JSON（FocusResult），出错 exit 1 并打印 `{error}`。**所有开发与自测只允许 `--dry-run`**（真实 switch/create 会改变用户屏幕，由协调者验证）。
4. 本机可用于 dry-run 自测的在线会话：`02998b64-f0d0-48a9-9bf1-8c90e265de7a`（期望 `action:"switched"`，handle 形如 `term_…`）。

### R9 HTTP 服务（`src/server.ts`）
- 启动顺序：建库 → `indexAll()`（打印 `indexed N sessions in X ms`）→ `startRescanTimer()` → `Bun.serve({hostname:"127.0.0.1", port})` → 打印 `orcatab listening on http://127.0.0.1:<port>`。
- 路由：
  - `GET /` → `public/index.html`（`Content-Type: text/html; charset=utf-8`）。
  - `GET /healthz` → `{ok:true, sessions:number, indexedAt:number|null, version:"p1"}`。
  - `GET /api/projects` → `ProjectRow[]`，按 `lastInputAt DESC NULLS LAST`；`sessionCount` 与 `lastInputAt` 由 sessions 聚合。
  - `GET /api/sessions?project=<key>&live=1&limit=<n>` → `SessionRow[]`（合并 live；`live=1` 只返回在线；limit 默认 500，上限 2000）。
  - `GET /api/search?q=<text>&limit=<n>` → `SearchResult[]`（q 为空或只有空白 → `[]`；limit 默认 50，上限 200）。
  - `POST /api/focus/:sid` → `FocusResult`；`GET /focus?uri=orcatab://claude/<sid>` → 同样逻辑，返回 `text/plain` 一行（`switched term_… | resumed term_… | manual <reason> <command>`），uri 非 `orcatab://claude/<uuid>` → 400。
  - 其他 → 404 `{error:"not found"}`。
- 所有 JSON 响应 `Cache-Control: no-store`；未捕获异常 → 500 `{error}` 并 `console.error` 带路由与堆栈。
- `server.ts` 只做路由与装配（< 200 行）；可导出 `createServer(opts)` 供测试用随机端口启动。

### R10 页面（`public/index.html`，原生 JS，无外部资源）
